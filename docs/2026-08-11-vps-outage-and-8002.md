# 2026-08-11：VPS 失联与 Streamable HTTP 改造

## VPS 失联事件

### 现象

- Ping、SSH 和所有公网端口同时超时；
- 主机商面板仍显示运行中；
- 依赖该主机的服务同时中断。

### 判断与处理

“运行中”只说明虚拟机状态，不代表公网路由正常。需要结合主机控制台、路由测试和服务端日志判断，不能仅凭面板状态断言 IP 被封或机房故障。

建议顺序：

1. 从不同网络测试 Ping、SSH 和业务端口；
2. 使用主机商控制台或 VNC 检查系统是否响应；
3. 检查网卡、路由、负载、内核和服务日志；
4. 若控制台正常但公网完全不可达，向主机商提交工单；
5. 为重要服务准备异机备份，避免单点故障。

## SSE 断连后改用 Streamable HTTP

长连接可能受到代码兼容性、NAT 空闲超时和跨网抖动影响。改用 Streamable HTTP 后，仍需正确配置认证、反向代理超时和重试。

下面只展示安全骨架。管理进程监听回环地址，token 从环境变量读取，同步命令放入工作线程，避免堵塞 ASGI 事件循环：

```python
import asyncio
import os
import subprocess

from mcp.server.fastmcp import FastMCP
from mcp.server.transport_security import TransportSecuritySettings

TOKEN = os.environ["MCP_BEARER_TOKEN"]
slots = asyncio.Semaphore(4)

mcp = FastMCP(
    "vps-mcp",
    host="127.0.0.1",
    port=int(os.getenv("MCP_PORT", "8000")),
    transport_security=TransportSecuritySettings(
        enable_dns_rebinding_protection=False
    ),
)

@mcp.tool()
async def run_command(command: str) -> str:
    async with slots:
        result = await asyncio.to_thread(
            subprocess.run,
            command,
            shell=True,
            capture_output=True,
            text=True,
            timeout=120,
        )
    return result.stdout[-3000:]
```

> `shell=True` 仍然意味着调用方可以执行任意命令。更安全的方案是把管理能力拆成参数化、可审计的固定工具，并让服务使用最小权限账户。

### 认证与日志

- 优先使用 `Authorization: Bearer <TOKEN>`；
- 不把 token 硬编码进源码；
- 不建议把 token 放在 URL 查询参数中；
- 如果旧客户端只能使用查询参数，应让该 Nginx location 使用不含 `$args` 的日志格式，并尽快迁移客户端后轮换 token；
- 只通过 Nginx 的 HTTPS 入口访问，后端端口不在 UFW 中开放。

### 验证

```bash
sudo nginx -t
systemctl status <MCP_SERVICE> --no-pager
ss -lntp | grep <MCP_PORT>       # 应监听 127.0.0.1
sudo ufw status                 # 不应公开后端端口

# 未认证请求应返回 401
curl -i https://<MCP_HOST>/mcp
```

DNS 重绑定保护不应为了方便 IP 直连而随意关闭。若因反向代理架构必须关闭，应同时确保后端仅监听回环地址、Nginx 校验 Host 且公网无法直连后端。
